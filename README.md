## Final Report

### 專案說明
<!-- 完整描述你的專案做了什麼 -->
在此專案中，我製作出一個具備九種功能的復盤記事錄，分別為加入事件、移除事件、線性搜尋事件、氣泡搜尋事件、利用ID尋找事件、氣泡排序、快速排序、顯示視窗、顯示行事曆(如同一般行事曆，可以另外顯示出有事件的日期，並加以查看)，加入事件及移除事件是對一開始執行時所建立的txt檔案進行操作，搜尋以及排序是先將檔案內的資料載入一個陣列再加以操作(每呼叫一次就需要重新建立陣列，在資料過多時效率將降低，應該將資料另外儲存以避免需要重複載入文件)，顯示視窗是利用AI輔助下利用WindowProc做出來的，會將在檔案中的文件一件一件縣市出來，依照星期幾來分類，會將精確的時間以及描述顯示出來，顯示行事曆是利用手刻出來的使用者介面，可以顯示各個月並將有寫入事件的日期以中括號括起來，可以選擇是否要看某一天的事件。


### 使用方式
<!-- 如何編譯、執行、使用你的程式 -->
將main2.cpp的內容貼於編譯器上(Windows的如果是用VScode的話需要另外下載編譯器，因為它是文字編譯器無法編譯)，按下編譯並執行，在相同的專案底下會產生events.txt這個檔案，所有關於檔案的操作都是對此檔案。執行後會先跳出一個Windows視窗(如果編譯失敗，或許是因為權限問題)，關閉後才會開始顯示出使用者介面，選擇功能要以開頭的編號來輸入，要加入檔案需要寫上精確日期時間，日期格式為xxxx-xx-xx，時間格式為xx-xx，如果不符合以上格式將無法輸出此事件，在移除事件時有最後的防護措施以避免刪錯事件，任一排序功能在排完序後，檔案內的事件也會修正成排序後的結果(來改善由時候ID會莫名跳躍的問題)，搜尋功能可打任何關鍵字，但是大小寫不一樣，且空格也會影響，顯示行事曆可以查看有事件的日期其描述為何，僅需輸入那一天的日期即可(eg.20)。

一、資料結構(Data Structure)的應用

本專題中主要使用了以下資料結構：

1. vector<Event>
vector<Event> events;
用途

用來儲存所有事件資料。

特性
動態陣列(dynamic array)
支援快速尾端新增
可搭配排序與搜尋演算法
優點
存取速度快（O(1) random access）
適合排序
缺點
中間刪除元素成本高
搜尋效率較低（若未排序）
2. map<int, Event>
map<int, Event> eventMap;
用途

利用 ID 快速搜尋事件。

特性
底層通常為 Red-Black Tree（紅黑樹）
自動排序 key
優點
搜尋效率高
插入與刪除穩定
缺點
記憶體消耗較大
不適合大量 sequential traversal
3. set<int>
set<int> reminded;
用途

避免提醒視窗重複跳出。

特性
元素不可重複
自動排序
優點
快速判斷元素是否存在
適合去重(de-duplication)
缺點
不保留插入順序
空間成本較高
二、演算法(Algorithm)的應用

本專題中實作了多種搜尋與排序演算法，並能比較其效率差異。

三、搜尋演算法比較
1. Linear Search（線性搜尋）
for (const auto& e : events)
原理

從頭逐一比對資料。

時間複雜度
O(n)
優點
簡單
不需排序
缺點
資料量大時效率差
2. Binary Search（二元搜尋）
sort(...)

後：

while (l <= r)
原理

每次將搜尋範圍縮小一半。

時間複雜度
O(log n)
優點
搜尋效率高
缺點
必須先排序
不適合頻繁新增刪除資料
3. Map Search
map<int, Event>
原理

利用平衡樹結構搜尋 key。

時間複雜度
O(log n)
優點
插入與搜尋都穩定
不需手動排序
缺點
記憶體使用較高
常數成本較大
四、搜尋演算法差異比較
演算法	時間複雜度	是否需排序	適用情境
Linear Search	O(n)	不需要	小型資料
Binary Search	O(log n)	需要	大量靜態資料
Map Search	O(log n)	自動排序	動態資料管理
