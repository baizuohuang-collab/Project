## Final Report

### 專案說明
<!-- 完整描述你的專案做了什麼 -->
在此專案中，我製作出一個具備九種功能的復盤記事錄，分別為加入事件、移除事件、線性搜尋事件、氣泡搜尋事件、利用ID尋找事件、氣泡排序、快速排序、顯示視窗、顯示行事曆(如同一般行事曆，可以另外顯示出有事件的日期，並加以查看)，加入事件及移除事件是對一開始執行時所建立的txt檔案進行操作，搜尋以及排序是先將檔案內的資料載入一個陣列再加以操作(每呼叫一次就需要重新建立陣列，在資料過多時效率將降低，應該將資料另外儲存以避免需要重複載入文件)，顯示視窗是利用AI輔助下利用WindowProc做出來的，會將在檔案中的文件一件一件縣市出來，依照星期幾來分類，會將精確的時間以及描述顯示出來，顯示行事曆是利用手刻出來的使用者介面，可以顯示各個月並將有寫入事件的日期以中括號括起來，可以選擇是否要看某一天的事件。


### 使用方式
<!-- 如何編譯、執行、使用你的程式 -->
將main2.cpp的內容貼於編譯器上(Windows的如果是用VScode的話需要另外下載編譯器，因為它是文字編譯器無法編譯)，按下編譯並執行，在相同的專案底下會產生events.txt這個檔案，所有關於檔案的操作都是對此檔案。執行後會先跳出一個Windows視窗(如果編譯失敗，或許是因為權限問題)，關閉後才會開始顯示出使用者介面，選擇功能要以開頭的編號來輸入，要加入檔案需要寫上精確日期時間，日期格式為xxxx-xx-xx，時間格式為xx-xx，如果不符合以上格式將無法輸出此事件，在移除事件時有最後的防護措施以避免刪錯事件，任一排序功能在排完序後，檔案內的事件也會修正成排序後的結果(來改善由時候ID會莫名跳躍的問題)，搜尋功能可打任何關鍵字，但是大小寫不一樣，且空格也會影響，顯示行事曆可以查看有事件的日期其描述為何，僅需輸入那一天的日期即可(eg.20)。
### 演算法與資料結構比較
<!-- 總結你的專題與進階程式設計及資料結構課程之間的關聯 -->

一、搜尋演算法比較

本專題實作了三種搜尋方式：

Linear Search（線性搜尋）
Binary Search（二元搜尋）
Map Search（映射搜尋）
(1) Linear Search 與 Binary Search 比較
Linear Search

原理：

從第一筆資料開始逐筆比較。

for (const auto& e : events)
{
    if (e.desc == key)
    {
        ...
    }
}

時間複雜度：

O(n)

其中 n 為資料筆數。

Binary Search

原理：

先將資料排序，再利用「每次排除一半資料」的方式搜尋。

時間複雜度：

O(logn)
比較結果
項目	Linear Search	Binary Search
時間複雜度	O(n)	O(log n)
需不需要排序	不需要	需要
實作難度	低	中
資料量小時	差異不大	差異不大
資料量大時	效率較差	效率較高
結論

當資料量較少時，Linear Search 較容易實作；但當資料量增加時，Binary Search 的效率遠高於 Linear Search，因此較適合大型資料搜尋。

二、排序演算法比較

本專題實作：

Bubble Sort
Fast Sort (std::sort)
(1) Bubble Sort

原理：

重複比較相鄰元素，若順序錯誤則交換。

例如：

5 3 4 1

↓

3 5 4 1

↓

3 4 5 1

↓

3 4 1 5

直到完成排序。

時間複雜度：

O(n
2
)
(2) Fast Sort（std::sort）

原理：

C++ STL 的 sort() 採用 IntroSort。

IntroSort 結合：

Quick Sort
Heap Sort
Insertion Sort

時間複雜度：

O(nlogn)
比較結果
項目	Bubble Sort	Fast Sort
時間複雜度	O(n²)	O(nlogn)
執行速度	慢	快
程式碼難度	簡單	直接呼叫
適合資料量	小型資料	大型資料
實際應用	教學用途	工業用途
結論

Bubble Sort 雖然容易理解，但效率較差；Fast Sort 具有較佳效能，因此本專題在實際排序功能中較適合使用 Fast Sort。

三、資料結構比較

你的專題主要使用：

vector
map

這也是老師常要求寫的部分。

Vector 與 Map 比較
Vector
vector<Event> events;

特性：

連續記憶體儲存
可利用索引快速存取

存取時間：

O(1)

搜尋時間：

O(n)
Map
map<int, Event> eventMap;

特性：

使用紅黑樹(Red-Black Tree)
自動排序

搜尋時間：

O(logn)

新增時間：

O(logn)
比較結果
項目	Vector	Map
底層結構	動態陣列	紅黑樹
存取速度	O(1)	O(log n)
搜尋速度	O(n)	O(log n)
是否自動排序	否	是
記憶體使用	較少	較多
結論

Vector 適合儲存大量資料並進行排序，而 Map 適合依照 ID 快速搜尋資料。因此本專題同時使用兩者，以兼顧資料儲存效率與搜尋效率。
